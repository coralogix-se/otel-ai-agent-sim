# Conventions

- `F_ws` — Workspace chip (`filters().team`, `CODEX_WORKSPACE_FILTER_KEY = 'team'`) as `workspace_id="…"`, several values `workspace_id=~"a|b"` (regex-escaped), absent when unset; inserted after the pinned matchers. No metric carries a workspace name.
- User chip — never a PromQL matcher. Keys are the identity email when known, else the compliance `user_id`; applied client-side on rows that carry a user (source IPs, remote control, the summary's remote-control count). Metrics without a user label are **not queried** under a User chip (`isUserScoped`): environments, patch PRs, access geo, audit counts.
- Model is never set: the bar renders only User and Workspace, and the filter store (`CxaiFiltersStore`) is in-memory per page, so no `model` matcher reaches any read, drawers included.
- `W` = `[Nd]`, N = max(1, ceil((to − from) / 1 day)); `S` = `[max(2, N)d]` for daily snapshots. Bounds from `cxAiTimeRange()`; a missing / non-numeric / reversed URL range falls back to **the last 7 days ending now** (`codexComplianceWindow`). Snapshot rows are cut to each workspace's newest `date` client-side (`latestPerWorkspace`); source-IP dates are re-clipped to [floor(from, day), to].
- `CT(R)` (`openai-shared/compliance/compliance-counters.ts`) = `(sum_over_time(R) * (max_over_time(R) <= bool clamp_min(resets(R), 1)) + (max_over_time(R) + resets(R)) * (1 - (max_over_time(R) <= bool clamp_min(resets(R), 1))))` — per series: sum when points are one event each, max + resets when the series is a running total.
- `CM` = `service_name!="cx-codex-compliance-puller"`. Applied only to access geo, the directory identity and feed lag.
- `{ID}` = two optional, unfiltered instants: `count by (user_id, user_email) (last_over_time(openai_analytics_codex_credits[30d]))` and `count by (user_id, email, user_email) (last_over_time(openai_compliance_user_identity{service_name!="cx-codex-compliance-puller"}[30d]))`. Precedence: directory (`email`, else `user_email`) > Analytics > raw-log member list (ids neither names). Several emails per id → lexically smallest.
- Evaluation: every instant runs at `time = floor(to/1000)` except feed freshness (at `Date.now()`). The page calls `pinQuickModeAnchor(true)`, so quick-mode "now" is fixed for the visit and deferred panels resolve the same `to`.
- Caching: `PrometheusQueryService` is provided on the page (separate from the shell's): key = (query, eval second), `shareReplay`, 30 s timeout, failures evicted. On top, whole reads are shared by `JSON([window, filters])`: source IPs (20 kept), environments (20), member list (4), former members (4); a failed or failed-open raw read evicts its entry and every result built from it.
- PromQL failure: a non-`optional` query fails its method → panel error state. `optional` (sweep, `{ID}`, feed lag) → empty vector.
- DataPrime: `RL(stream)` = `source default/ai.raw.openai.compliance_logs | filter $d.stream == 'openai.compliance.<stream>'`, further clauses joined with `&&`. Window = picker window [from, to]; archive tier (service default); `limit: 5000` (`RAW_LOG_ROW_LIMIT`); 30 s timeout; error / timeout / no `AiCenterDataprimeService` → `[]`.
- `SC` (event streams `codex`, `auth`) = `$d.data.principal.id == '<ws>'` (several → `(… || …)`) and `($d.data.actor.user_email == '<u>' || $d.data.actor.user_id == '<u>')`; values single-quote-escaped. Snapshot streams filter by suffix: `$d.data.creator_id.endsWith('__<ws>')`, `$d.data.account_user_id.endsWith('__<ws>')`. `users` stream reads are unfiltered.
- Row-limit rule: a raw read returning 5,000 rows is treated as cut — environments and audit fall back to the metric rows, remote devices and the newest-auth-event map are dropped (columns hidden), sign-ins re-read failures only and merge. Member, former-member and threads reads have no cut check.
- Identity: row key = identity email || `user_id`; several `user_id`s with one email merge into one row (`userIds[]`). Snapshot-stream ids (`user-…__<workspace>`) are stripped by `bareUserId`; event-stream `actor.user_id` is used as is. A row is clickable only when its email is known.
- Flag model: no `injectFeatureFlag` inside `codex-compliance-dashboard/`. `ai-center-openai-administration-usage` gates the route, the sidebar row (live) and the shell's product set (snapshot). In the user drawer, Run Time and Tools Used run when `ai-center-openai-codex` **or** `ai-center-openai-administration-usage` is ON — always ON here except after a mid-session flip. `ai-center-openai-codex` also decides `CodexReposService`'s CLI-log fallback; `ai-center-managed-repos-settings` (snapshot) shapes the drawer's repo charts.

# Appendix — dead / duplicated queries

1. ⚠ Dead output: Security scans issues no query; "Critical security findings" can never fire; the patch-PR insight never gets a CTA or repository count (`patchPrs: []`); the Credential column and `lastTaskMs` are always null.
2. ⚠ Producer exclusion is partial: `service_name!="cx-codex-compliance-puller"` guards only access geo, the directory identity and feed lag. `events_total` reads (`sum by` through `CT()` — audit counts, patch PRs, the shell's detection probe) would double-count any puller series still inside the window; the `max by` snapshot reads collapse duplicates.
